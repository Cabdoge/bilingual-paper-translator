# 模型分工、解析与批次交接

## 获取原文

先检查用户提供的实际文件。原 TeX 是内容输入，不是排版模板：展开所需正文文件、数学宏及书目关系，再按本 skill 的结构重排。只读取和暂存该论文需要的依赖，不复制整个 Zotero 数据目录。缺少依赖时处理可确认内容并说明缺项。

同时存在 PDF/TeX 时核对标题、版本、章节和编号；真正的内容差异需要用户指定采用版本，普通源码格式差异不构成冲突。无原 PDF 时，在临时副本内编译原源码，副本保留必要的用户提供依赖；编译失败不能假称已获得原版面。

只有 PDF 时：

1. 已有 MinerU 结果且与当前 PDF 对应时复用；否则本机可用 MinerU 时先运行。
2. 在这台机器上优先检查 `/Users/1tianpang/Zotero/Zotero-Analytical-Workflow-Skills/config.toml` 及 `tools/run_mineru_production.py`。可用时用该仓库配置的 Python 与转换脚本，显式指定工作目录里的全新 extraction 子目录。不要触发 Vault 入库或改 Zotero 数据库。
3. 本机路径不存在时发现当前可用的 MinerU；无可用转换工具才交由 Luna 解析。不要为了完成这项任务自动安装服务或把原文上传其他平台。
4. Luna 仅补查实际失败/存疑区域；完全无解析时按页段并行。页段边界保留必要的上下文/重叠，并记录页码。Sol 合并时去重，复核跨页段落、定理、公式和表格。

MinerU Markdown 的断行、段落、公式与编号均需核验；不得据它恢复首行缩进。英文原文也要恢复正确阅读顺序，不能只校对中文。

## 术语与分块

Sol 先通览全文：术语表记录英文、中文或保留英文、人名、上下文/定义位置与当前版本。作者自定义且不易译的名称允许保留英文；不给所有陌生术语一律强行翻译。

对象目录区分本文与外部文献、对象类型和原编号；用稳定 ID 及语言后缀建立目标，例如 `bpt:u0012:en` / `bpt:u0012:zh`。手写 “Theorem 6 in [15]” 不等于本文的 Theorem 6。不要按数字全局替换链接。

分块依据原文自然段和数学环境。标题、定理陈述、独立行间公式、图表分别标注类型。保留原段落身份，区分公式后的续接文字与新自然段。完整定理不能为分派任务拆开；证明可以按原自然段分块。

## 试译与并行

选一个包含术语、数学条件和证明等内容的小节试译。Sol 复核后形成可执行反馈，再扩大并行；这一步不默认等待用户审批。

按语义连续的 pair 组派任务。普通章节可一章一个任务；长章按小节分组，依据内容长度调整，不硬塞整章或把每个短 pair 单独派一个代理。默认每批 2–3 个 Luna，扣除已活跃主控/子代理所占额度，避免超额。

每个 Luna 任务必须得到：

- 此 skill 路径、translation.md、指定模型/档位。
- 只读原文块文件和确切的 assigned IDs；术语表版本与相关术语。
- 本节背景、相关定义/符号、必要的前后段落；全文信息可以查阅，不凭空猜指代。
- 独立结果文件路径；要求原文块不改、只返回中文与疑点。

输出严格遵循 workspace.md。子代理不同时编辑正式译稿，不自行改变编号、公式、术语规则、输入类型或 pair 划分。新增术语/歧义提交给 Sol。复用空闲 Luna 时保留其模型设置，并重新给完整任务材料；不依赖它记得别的代理的决定。

## 每批与最终复核

Sol 先检查 assigned IDs 一对一完整覆盖、英文哈希和术语版本，再逐块看译文。发现问题直接修正或要求对应 Luna 定向重做；反馈写明 pair ID、具体问题、适用范围与修正要求。

术语改变时更新版本并定位此前受影响的块，修正后重新标记复核状态；不机械要求全文重译。不接受“已完成”宣告来替代文件及覆盖检查。失败的批次保留进度，不把缺项当空译文写入最终稿。

全篇首次术语呈现由 Sol 最终统一，不能让每批都重复首现括注。末轮核验跨节符号、术语、量词/否定、定理条件、公式、页段接续、图表与编号；编译和链接检查是另一层。

不能控制主会话模型时，调用一个 `gpt-6.1-sol` / `high` 工作代理执行 Sol 阶段，再由其按可用额度调用 `gpt-6-luna` / `xhigh`。不要用 API 代码、购买额度或新建侧栏任务来绕过本环境能力；不可用时诚实说明并保留状态。
